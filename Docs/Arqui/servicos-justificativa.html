Por que cada serviço está no desenho

Plataforma de investimentos — serviço stateless de integração. Fase 1: Fundos. Cada item traz o motivo de estar na arquitetura, o que quebra se for retirado e a alternativa possível. Documento complementar ao diagrama arquitetura-investimentos-aws-v5.drawio.

2Borda

Amazon Route 53

DNS público do BFF

Condicional 
graph LR
  A["Cliente"] --> B["Route 53"] --> C["API Gateway"]

Por que está no desenhoResolve o domínio que o cliente digita para o endpoint do API Gateway. É onde você controla o nome público, o TTL e um eventual failover entre regiões.

O que acontece se tirarNada quebra se o domínio já é gerenciado em outro DNS (registro.br, Cloudflare, DNS corporativo). Você só perde a integração nativa com ACM e health check da AWS.

AlternativaQualquer DNS autoritativo. Aponte um CNAME para o endpoint do API Gateway.

AWS WAF

Filtro de requisição na borda

Condicional 
graph LR
  A["Cliente"] --> B["WAF"] --> C["API Gateway"]
  B -.bloqueia.-> D["descarta"]

Por que está no desenhoBloqueia injeção, varredura e abuso antes de gastar Lambda, BFF e — principalmente — cota dos gateways dos provedores. Rate limit por IP evita que um script consuma seu limite de 429 com o parceiro.

O que acontece se tirarVocê fica exposto a bot e enumeração no endpoint público. Em plataforma financeira isso costuma virar apontamento de segurança na primeira revisão.

AlternativaThrottling do próprio API Gateway resolve volume, mas não inspeciona conteúdo. Não substitui o WAF, complementa.

Amazon API Gateway (HTTP API)

Entrada única do BFF

Obrigatório 
graph LR
  A["WAF"] --> B["API Gateway HTTP API"]
  B --> C["Lambda Authorizer"]
  B --> D["VPC Link → BFF"]

Por que está no desenhoÉ a premissa do seu desenho: todo tráfego entra por aqui. Concentra TLS público, authorizer, throttling por cliente e o contrato público. É também o que permite os serviços de domínio não terem gateway próprio.

O que acontece se tirarSem ele você precisaria expor um ALB público e reimplementar auth, quota e contrato em cada serviço — exatamente o anti-padrão descartado no início.

AlternativaALB público + autenticação no BFF. Mais barato em volume alto, mas você perde authorizer gerenciado, quota por cliente e o modelo de contrato.

AWS Lambda — Authorizer

Autorização própria antes de rotear

Condicional 
graph LR
  A["API Gateway"] -->|1. valida| B["Lambda Authorizer"]
  B -->|allow + context| A
  A -->|2. roteia| C["BFF"]
  B -.-> D["IdP / chaves públicas"]

Por que está no desenhoO API Gateway chama a Lambda antes de rotear. É onde entra a autorização que é sua, não do IdP: perfil do investidor, suitability, produto habilitado para aquele cliente, escopo por rota. Ela devolve allow/deny mais um context (CPF, perfil, conta) que o BFF propaga adiante sem precisar reabrir o token.

O que acontece se tirarSe a regra for apenas “o token é válido?”, o JWT authorizer nativo do HTTP API faz isso sem Lambda — sem cold start, sem custo por invocação e sem mais um artefato para versionar. Só coloque a Lambda quando houver regra de negócio na autorização.

AlternativaJWT authorizer nativo (regra simples) ou autorização dentro do próprio BFF (mas aí o serviço passa a confiar em quem chamou, e a decisão sai da borda).

Custo / atençãoCobrada por invocação. Ligue o cache do authorizer com TTL: o mesmo token não precisa de nova invocação a cada requisição.

Amazon Cognito

Emissão e validação de identidade

Condicional 
graph LR
  A["Cliente"] --> B["Cognito / IdP"] -->|JWT| A
  B -.chaves públicas.-> C["Lambda Authorizer"]

Por que está no desenhoEmite o token que o cliente apresenta e expõe as chaves públicas que o authorizer usa para validar assinatura.

O que acontece se tirarSe já existe IdP corporativo (Keycloak, Entra ID, Auth0, o IdP do banco), use ele — o desenho não muda, só a origem das chaves.

AlternativaQualquer provedor OIDC. O Lambda Authorizer valida a assinatura da mesma forma.

3BFF

Amazon ECS Fargate (BFF)

Compute do agregador

Obrigatório 
graph LR
  A["API Gateway"] -->|VPC Link| B["BFF — ECS Fargate"] --> C["ALB interno"]

Por que está no desenhoO BFF precisa de compute. Fargate mantém conexão viva (keep-alive) com o ALB interno, não tem cold start e o mesmo padrão de task vale para BFF e domínio — um blueprint só para o time aprender.

O que acontece se tirarNão existe BFF sem compute. A escolha real é Fargate x Lambda.

AlternativaLambda: mais barato em tráfego baixo e intermitente, mas cold start e pool de conexão por invocação atrapalham quando a rota chama 4 gateways externos.

VPC Link

Ponte privada do API Gateway para a VPC

Obrigatório 
graph LR
  A["API Gateway"] --> B["VPC Link"] --> C["BFF na subnet privada"]

Por que está no desenhoÉ o que permite o API Gateway alcançar um recurso privado. Sem ele, o gateway só chama endpoint público — e aí o BFF precisaria de IP público.

O que acontece se tirarVocê seria forçado a expor o BFF na internet. Quebra a premissa de entrada única controlada.

AlternativaNenhuma, dentro deste desenho. É componente de ligação, não uma escolha.

4Roteamento interno

Application Load Balancer (interno)

Endpoint privado + roteamento por path

Obrigatório 
graph LR
  A["BFF"] --> B["ALB interno"]
  B -->|/fundos/*| C["tg-fundos"]
  B -.->|/cdb/*| D["tg-cdb (fase 2)"]
  B -.->|/renda-fixa/*| E["tg-renda-fixa (fase 3)"]

Por que está no desenhoDá ao serviço de Fundos um endpoint privado sem gateway próprio, e é o ponto onde CDB e Renda Fixa entram depois: cada fase nova é um target group e uma regra de path. Também entrega health check, deploy blue/green e mTLS opcional no listener.

O que acontece se tirarSem ele, ou o BFF chama IP de task (frágil, muda a cada deploy) ou você cria um segundo API Gateway — o anti-padrão já descartado.

AlternativaECS Service Connect para tráfego leste-oeste. Não substitui o ALB no caminho BFF → domínio quando você quer blue/green por target group.

ECS Service Connect / Cloud Map

Descoberta entre serviços

Opcional 
graph LR
  A["ECS cdb (fase 2)"] -->|http://fundos:8080| B["ECS fundos"]

Por que está no desenhoÚtil quando, na fase 2, o serviço de CDB precisar consultar Fundos direto. Resolve por nome DNS curto, sem passar por load balancer.

O que acontece se tirarNa fase 1 não faz falta: só existe um serviço de domínio, e o BFF já chega nele pelo ALB.

AlternativaChamar via ALB interno também funciona — custa um hop a mais e não dá métrica por serviço.

5Aplicação

Amazon ECS Fargate (fundos)

Compute do serviço de domínio

Obrigatório 
graph LR
  A["ALB interno"] --> B["ECS Fargate — fundos"] --> C["lib provider-clients"] --> D["gateways externos"]

Por que está no desenhoRoda o Java com o modelo hexagonal. Fargate foi escolhido por manter pool de conexão vivo com os 4 gateways externos — o que reduz handshake TLS e mTLS por requisição — e por não ter cold start numa chamada que já depende de 4 terceiros.

O que acontece se tirarNão há serviço sem compute.

AlternativaLambda (cold start + pool novo a cada invocação atrapalham a integração) ou EC2 (você passa a gerenciar patch e AMI).

Amazon ECR

Registro da imagem do container

Obrigatório 
graph LR
  A["CI do serviço"] --> B["ECR"] --> C["ECS task"]

Por que está no desenhoÉ de onde o ECS puxa a imagem. Fica na mesma conta e região, com scan de vulnerabilidade e política de retenção.

O que acontece se tirarSem registro não há deploy de container.

AlternativaDocker Hub ou o registro do próprio Artifactory. Funciona, mas adiciona egress e credencial para o ECS puxar imagem.

Caffeine (biblioteca, não serviço)

Cache em processo

Opcional 
graph LR
  A["App Java"] --> B{"Caffeine"}
  B -->|hit| A
  B -->|miss| C["gateway externo"]

Por que está no desenhoEvita ida ao gateway externo para dado que não muda: token OAuth2, cadastro de fundo, calendário. Zero infraestrutura nova — vive no heap da própria task.

O que acontece se tirarCada requisição do cliente vira requisição ao provedor. Isso consome sua cota de 429 e adiciona latência que você não controla.

AlternativaElastiCache, mas só quando o cache precisar ser o mesmo para todas as tasks.

Custo / atençãoCusta memória da task. Limite por número de entradas (maximumSize), não por “até encher”.

ElastiCache Serverless for Valkey

Estado compartilhado entre tasks

Opcional 
graph LR
  A["ECS task 1"] --> C["ElastiCache Valkey"]
  B["ECS task 2"] --> C

Por que está no desenhoEntra na fase 2, quando existir algo que precise ser igual para todas as tasks: dedup de webhook, lock, rate limit global contra o gateway do provedor. Valkey e não Redis OSS — é drop-in, mais barato e é o motor que a AWS recomenda para deployment novo.

O que acontece se tirarNada, na fase 1. O Caffeine cobre o que você precisa hoje.

AlternativaDynamoDB com TTL para chave de idempotência — mais barato e sem cluster, com a vantagem de ser durável (o ElastiCache é memória volátil).

Custo / atençãoServerless tem piso mensal mesmo vazio. Nó t4g.micro sai mais barato para uso pequeno e constante.

6Configuração

AWS Systems Manager Parameter Store

Endpoints e parâmetros por ambiente

Obrigatório 
graph LR
  A["Parameter Store"] -->|boot| B["App Java"] --> C["gateway externo"]

Por que está no desenhoÉ onde vivem base-url, basePath, path por operação e timeout por endpoint. Trocar a URL de homologação de um provedor vira mudança de parâmetro, não build e deploy — e o mesmo artefato sobe em dev, hml e prd.

O que acontece se tirarOs endpoints voltam para variável de ambiente do task definition ou, pior, para dentro do código. Toda mudança de URL vira release.

AlternativaAppConfig (validação e rollout gradual) ou o próprio Artifactory servindo arquivo de configuração. Parameter Store é o mais simples e tem tier grátis.

AWS Secrets Manager

Credenciais dos gateways e do Artifactory

Obrigatório 
graph LR
  A["Secrets Manager"] -->|runtime| B["lib provider-clients"] --> C["gateway com mTLS"]

Por que está no desenhoGuarda subscription key, client secret, certificado mTLS e o token de leitura do Artifactory usado pelo CI. Nada disso pode entrar na imagem nem no repositório.

O que acontece se tirarCredencial em variável de ambiente versionada ou em imagem — o achado mais comum em auditoria.

AlternativaParameter Store SecureString: mais barato, mas sem rotação automática e sem versionamento de segredo.

AWS Private CA

Emissão de certificado cliente para mTLS

Condicional 
graph LR
  A["Private CA"] -->|cert cliente| B["Secrets Manager"] --> C["lib provider-clients"]

Por que está no desenhoSó é necessário se algum gateway exigir mTLS e aceitar certificado emitido por CA sua.

O que acontece se tirarNada, se os provedores emitem o certificado cliente (é o caso mais comum). Aí basta guardar o que eles mandaram no Secrets Manager.

AlternativaCertificado emitido pelo próprio provedor. Confirme isso na ficha do gateway antes de provisionar — a Private CA tem custo mensal fixo relevante para uso pequeno.

AWS AppConfig

Feature flag por gateway

Opcional 
graph LR
  A["AppConfig"] -->|flag| B["App Java"]
  B -.desliga.-> C["gateway em incidente"]

Por que está no desenhoPermite desligar um provedor em incidente sem subir versão — útil quando um dos 4 gateways cai e você quer degradar a funcionalidade em vez de derrubar a rota.

O que acontece se tirarVocê depende de deploy para desligar uma integração. Em incidente, isso é lento.

AlternativaParâmetro booleano no Parameter Store lido com TTL curto. Resolve 80% do caso sem serviço novo.

Amazon S3 + Object Lock

Trilha imutável de requisição e resposta

Condicional 
graph LR
  A["App Java"] -->|payload| B["S3 Object Lock"]
  B -.retenção.-> C["auditoria"]

Por que está no desenhoComo não há banco, é o único lugar onde fica prova do que foi enviado e recebido de cada provedor. Object Lock impede alteração e exclusão durante o período de retenção.

O que acontece se tirarVocê não consegue reconstruir o que aconteceu numa ordem contestada. Sem banco, o log do Datadog tem retenção limitada e não é prova imutável.

AlternativaNenhuma boa. Se houver exigência regulatória de retenção, isso deixa de ser opcional — vale confirmar com compliance antes de fechar a fase 1.

7Saída

NAT Gateway + Elastic IP

Saída com IP fixo para allowlist

Obrigatório 
graph LR
  A["ECS fundos"] --> B["NAT + EIP fixo"] --> C["Internet"] --> D["gateways dos provedores"]

Por que está no desenhoOs gateways dos provedores quase sempre exigem allowlist de IP de origem. O EIP dá esse IP fixo, e permite que as tasks fiquem em subnet privada sem IP público.

O que acontece se tirarOu você põe IP público nas tasks (o IP muda a cada deploy e quebra a allowlist), ou não consegue sair para os provedores.

AlternativaNAT instance (mais barato, mas vira sua responsabilidade operacional) ou saída via firewall corporativo por Direct Connect.

Custo / atençãoCobra por hora e por GB processado. É um dos itens de custo fixo mais visíveis do desenho.

Internet Gateway

Rota de saída da VPC

Obrigatório 
graph LR
  A["NAT Gateway"] --> B["Internet Gateway"] --> C["Internet"]

Por que está no desenhoComponente da VPC que dá saída à internet. O NAT depende dele.

O que acontece se tirarNão há saída para os provedores.

AlternativaNenhuma, se os provedores estão na internet pública.

VPC Endpoints (PrivateLink)

Acesso privado a serviços AWS

Opcional 
graph LR
  A["ECS task"] --> B["VPC Endpoint"] --> C["Secrets Manager / ECR / S3"]

Por que está no desenhoFaz as chamadas a Secrets Manager, Parameter Store, ECR e S3 saírem pela rede da AWS em vez de passar pelo NAT — reduz o volume cobrado no NAT e tira esses acessos da internet.

O que acontece se tirarTudo continua funcionando, passando pelo NAT e pagando por GB.

AlternativaNenhuma necessária. É otimização de custo e postura de rede, não requisito.

8Provedores

Gateways das 4 APIs externas

Dado do problema

Fora da AWS 
graph LR
  A["lib provider-clients"] --> B["Gateway do provedor"]
  B --> C["/endpoint 1"]
  B --> D["/endpoint 2"]
  B --> E["/endpoint N"]

Por que está no desenhoCada provedor expõe um gateway: um host, N endpoints. A cota de throttling (429) é do host e compartilhada por todos os endpoints dele — por isso pool, bulkhead e circuit breaker são por gateway, e timeout é por endpoint.

O que acontece se tirarNão é uma escolha sua. O que é escolha é como você se protege deles.

9Artifactory

JFrog Artifactory

Repositório Maven privado da lib

Obrigatório 
graph LR
  A["repo lib-provider-clients"] --> B["CI da lib"] --> C["Artifactory"]
  C -.dependência.-> D["CI do svc-fundos"] --> E["ECR"]

Por que está no desenhoA lib provider-clients vive em repositório Git próprio e é publicada aqui como JAR versionado. É isso que separa o ciclo de vida: a lib muda quando o provedor muda, o serviço muda quando a regra de negócio muda. As fases 2 e 3 consomem a mesma versão publicada, sem copiar código.

O que acontece se tirarRepositórios juntos forçam deploy do serviço a cada ajuste de transporte, e as três fases acabam com cópias divergentes do mesmo client.

AlternativaAWS CodeArtifact, se quiser ficar 100% AWS — o desenho não muda, só a URL do repositório.

Custo / atençãoSe o Artifactory for self-hosted no on-premises, o CI precisa de Direct Connect, VPN ou PrivateLink para alcançá-lo. Vale confirmar antes de provisionar.

AWS CodeBuild / CodePipeline

Execução do build

Condicional 
graph LR
  A["Git"] --> B["CI"] --> C["Artifactory / ECR"]

Por que está no desenhoRoda o build da lib e o do serviço, com credencial vindo do IAM em vez de token estático.

O que acontece se tirarNada, se você já usa GitHub Actions, GitLab CI ou Jenkins. O importante é que existam dois pipelines separados, um por repositório.

AlternativaQualquer CI. O requisito real é: build reproduzível, sem SNAPSHOT em homologação e produção, e versão fixada no pom.

TransversalTransversal

IAM — Task Role e Execution Role

Identidade da aplicação

Obrigatório 
graph LR
  A["ECS task"] -->|Task Role| B["Parameter Store / Secrets Manager"]
  C["Agente ECS"] -->|Execution Role| D["ECR"]

Por que está no desenhoTask Role dá à aplicação acesso a Parameter Store, Secrets Manager e AppConfig. Execution Role serve ao próprio ECS para puxar imagem e ler segredos no start. São papéis diferentes de propósito — não junte os dois.

O que acontece se tirarVocê acaba usando credencial estática dentro do container. É o caminho mais curto para um incidente de vazamento.

AlternativaNenhuma. É base da plataforma.

Security Groups

Autorização de rede entre camadas

Obrigatório 
graph LR
  A["SG do BFF"] --> B["SG do ALB"] --> C["SG das tasks"]

Por que está no desenhoÉ o que garante que ninguém pule o BFF: o SG do ALB aceita só o SG do BFF, e o SG das tasks aceita só o SG do ALB. Sem isso, a “entrada única” é convenção, não controle.

O que acontece se tirarQualquer recurso dentro da VPC passa a alcançar o serviço de domínio direto.

AlternativaNenhuma. Faz parte da VPC.

AWS KMS

Chaves de criptografia

Obrigatório 
graph LR
  A["KMS"] --> B["Secrets Manager"]
  A --> C["S3"]
  A --> D["ECR"]

Por que está no desenhoCriptografa segredos, parâmetros SecureString, imagens no ECR e objetos no S3. A chave gerenciada pela AWS já cobre o básico sem custo adicional.

O que acontece se tirarNão é opcional na prática — os serviços acima já usam KMS por padrão.

AlternativaChave gerenciada pelo cliente (CMK) quando houver exigência de rotação e política próprias. Aí passa a ter custo por chave.

Amazon CloudWatch

Telemetria nativa da plataforma

Obrigatório 
graph LR
  A["ALB / API Gateway / Fargate"] --> B["CloudWatch"] -.AWS Integration.-> C["Datadog"]

Por que está no desenhoOs serviços gerenciados (ALB, API Gateway, Lambda, Fargate) publicam métrica aqui de qualquer forma. É a fonte que a AWS Integration do Datadog lê.

O que acontece se tirarNão é uma escolha: existe por padrão. A escolha é quanto log você retém aqui — com FireLens mandando direto ao Datadog, dá para reduzir bastante.

AlternativaNenhuma. Você pode reduzir o uso, não eliminá-lo.

Datadog

Painel único de observabilidade

Condicional 
graph LR
  A["dd-java-agent"] --> D["Datadog"]
  B["FireLens"] --> D
  C["CloudWatch"] -.-> D

Por que está no desenhoJunta trace, log e métrica das 9 camadas numa correlação só, e permite monitor por gateway e por endpoint — que é onde quase toda falha nasce, já que o serviço é stateless.

O que acontece se tirarNada quebra tecnicamente. Você fica com CloudWatch e X-Ray, correlação mais trabalhosa e sem Synthetics por provedor.

AlternativaCloudWatch + X-Ray (nativo, mais barato) ou Grafana/OpenTelemetry (mais trabalho de operação).

Custo / atençãoCobrado por host e por volume de log. Em Fargate, cada task conta — dimensione a amostragem de trace antes de escalar.

Como ler os selos. Obrigatório: sem ele o desenho não funciona ou perde uma premissa (entrada única, IP fixo, sem credencial na imagem). Condicional: depende de uma resposta que ainda não está fechada — se há IdP corporativo, se o provedor exige mTLS com CA sua, se compliance exige trilha imutável. Opcional: melhora custo ou operação, e pode entrar depois sem retrabalho.

Três decisões continuam em aberto e valem confirmar antes de provisionar: se a autorização precisa de regra própria (define o Lambda Authorizer), se algum gateway exige mTLS com certificado emitido por você (define a Private CA), e se há exigência regulatória de reter requisição e resposta (define o S3 com Object Lock — que, sem banco, é a única prova que sobra).
